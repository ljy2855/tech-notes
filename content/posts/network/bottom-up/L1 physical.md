
학교 네트워크 수업은 보통 top-down으로 진행한다. OSI 7 layer를 위에서부터 내려오면서 배우는데, 이론 위주다 보니 지금은 잘 안 쓰는 내용도 많고 정작 실무에서 필요한 건 수업에서 안 다루는 경우가 상당히 많다.

그래서 이번 시리즈는 거꾸로 L1부터 L7까지 올라가 보려고 한다. (L7부터 하면 나중에 너무 재미없을것 같아서... 귀찮은 L1부터 후딱 쓰자...)

> on-premise 환경에서 웹서비스(혹은 CSP 사업)를 제공하려면 네트워크에서 뭘 고려해야 하는지 다룬다. (cloud service X)

- 수업에서 배운 네트워크를 IT 회사에서는 실무에 어떻게 녹이는지
- 수업에선 안 알려주지만 실제 업무엔 필요한 내용들

1편은 L1, 물리 계층이다.

## L1, 뭘 알아야 하나

수업에선 L1을 물리 계층, 즉 전기 신호나 빛, 전파 개념부터 설명한다. 유선/무선으로 나뉘는데, 여기선 서비스를 제공하는 server 쪽 관점이라 유선만 본다. (client는 대부분 무선이다)

> 이런 물리 얘기까지 알아야 하나?

깊게는 몰라도 된다. 실제 포설이나 장비 설치는 네트워크 담당자가 직접 하기보다 벤더나 통신 작업자분들께 맡기는 경우가 많다. 다만 IDC를 구성하다 보면 **어느 구간에 어떤 케이블과 모듈을 쓸지**는 직접 설계해야 하니, 이 두 가지는 알고 가자.

- Cable type (구리 vs 광)
- Transceiver

## 스위치 포트 두 종류

![[Pasted image 20261010155501.png]]

흔히 보는 네트워크 스위치다. 왼쪽에 빽빽하게 있는 게 익숙한 LAN 포트(RJ45)고, 오른쪽 끝 몇 개가 광 포트(SFP 계열)다.

| 항목 | LAN 포트 (RJ45) | 광 포트 (SFP) |
| --- | --- | --- |
| 케이블 | UTP (구리) | 광케이블 |
| 신호 | 전기 | 빛 |
| 속도 | 1G ~ 10G | 1G ~ 400G 이상 |
| 거리 | 최대 100m | 수백 m ~ 수십 km |
| 주 용도 | 서버 ↔ 스위치 | 스위치 ↔ 스위치 (uplink) |

> 서버는 구리로, 스위치끼리는 광으로 잇는다.

### UTP (RJ45)

케이블 안에 꼬인 구리선이 들어있고, 전기 신호로 데이터를 보낸다.

![[Pasted image 20261010160837.png]]

- 1G ~ 10G 정도, 거리는 최대 100m (전기 신호는 멀리 갈수록 감쇠가 심해서 빛보다 거리가 짧다)
- 10G를 100m까지 쓰려면 Cat6a 이상이 필요하다
- 아래쪽 FTP는 실드를 한 겹 감싼 버전이라 노이즈에 더 강하다

주로 서버를 스위치에 붙일 때 쓴다. 서버실에 들어가 보면 랙 상단에 스위치를 두고, 그 아래 서버들을 UTP로 연결해둔 걸 볼 수 있다.

### 광 (SFP)

스위치끼리 연결할 때 주로 쓰는 고속, 장거리용 포트다. 광 포트에는 케이블을 바로 꽂는 게 아니라, 전기 신호를 빛으로 바꿔주는 `transceiver`를 먼저 꽂아야 한다. 현장에선 그냥 지빅(GBIC)이라고들 부른다. (엄밀히 GBIC은 SFP 이전 세대 규격이다)

![[Pasted image 20261010161339.png]]

앞을 보면 구멍이 두 개 있다. 하나는 TX(송신, 진짜 빛을 쏜다), 다른 하나는 RX(수신)다. 그래서 광케이블도 두 가닥이 한 쌍으로 붙어 있다.

![[Pasted image 20261010161921.png]]

```text
Switch A                Switch B
  [TX] ----- fiber -----> [RX]
  [RX] <---- fiber ------ [TX]
```

> 한 가닥은 송신 전용, 한 가닥은 수신 전용이다.

#### 멀티모드 vs 싱글모드

광케이블은 빛을 보내는 방식(mode)에 따라 두 가지로 나뉜다.

| 항목 | 멀티모드 (MMF) | 싱글모드 (SMF) |
| --- | --- | --- |
| 거리 | 대략 100 ~ 400m | 10km ~ 수십 km |
| transceiver | 저렴 (SR) | 비쌈 (LR / ER / ZR) |
| 케이블 색 | 하늘색 (OM3/OM4) | 노란색 (OS2) |
| 주 용도 | 같은 홀 안, 랙 ↔ 랙 | 건물 간, DC 간 |

위 사진의 하늘색 케이블이 멀티모드다.

> 속도 차이가 아니라 **거리 차이**다. 싱글모드도 100G, 400G 다 된다. 멀리 갈수록 싱글모드

#### Transceiver 이름 읽기

모듈 이름에 필요한 정보가 다 들어있다.

```text
10G  SFP+  SR
 |    |     +-- 거리   : SR(멀티모드 ~300m) / LR(싱글모드 ~10km) / 
 |    +-------- 폼팩터 : 꽂을 포트 모양
 +------------- 속도
```

| 폼팩터 | 속도 |
| --- | --- |
| SFP | 1G |
| SFP+ | 10G |
| SFP28 | 25G |
| QSFP+ | 40G |
| QSFP28 | 100G |
| QSFP-DD / OSFP | 400G ~ 800G |

> 포트와 폼팩터가 맞아야 꽂히고, 양 끝 모듈 타입(SR-SR, LR-LR)이 같아야 링크가 올라온다.

## 랙 구성: 어디에 뭘 꽂나

![[Pasted image 20261010155834.png]]

랙에 서버를 배치할 때는 보통 맨 위에 스위치를 두고 아래 서버들을 붙인다. 이걸 ToR(Top of Rack) 구성이라고 한다.

예를 들어 서버 10대가 각각 500M 정도 대역폭이 필요하다면 이렇게 잡는다.

```text
need     : 500M x 10 servers = 5G     실제 트래픽
downlink : 1G UTP x 10       = 10G    서버 -> ToR
uplink   : 10G MMF x 1       = 10G    ToR -> 상위 스위치
```

서버 쪽 포트 합과 uplink의 비율을 oversubscription이라고 하는데, 여기선 10G : 10G로 1:1이라 여유롭다. 실제로는 장애 대비로 uplink를 2개 이상 묶어서 쓴다.

> 서버 쪽은 싸고 짧은 구리로, 트래픽이 모이는 uplink는 광으로 굵게 잡는다.

## DCI: DC끼리 잇기

데이터센터 이중화를 하려면 DC끼리 연결하는 DCI(Data Center Interconnect)가 필요하다. 이때는 물리적인 거리와 필요한 대역폭에 따라 어떤 링크로 구성할지가 달라진다. (물론 가격도 천차만별이다)

거리별로 보면 대략 이렇게 고른다.

| 거리 | 구간 | 주로 쓰는 것 |
| --- | --- | --- |
| ~수 m | 랙 안 (서버 ↔ ToR) | UTP, DAC |
| ~수백 m | 같은 홀 (ToR ↔ 상위 스위치) | 멀티모드 + SR |
| ~10km | 건물 간 | 싱글모드 + LR |
| 수십 km ~ | DC ↔ DC | 싱글모드 + ER/ZR, DWDM, 통신사 전용회선 |

- DAC: 양 끝에 SFP 모듈이 일체형으로 붙은 구리 케이블. 랙 안 짧은 구간에선 transceiver + 광케이블보다 싸서 서버 10G/25G 연결에 많이 쓴다

> 거리가 늘면 매체가 바뀌고, 매체가 바뀌면 모듈 값이 뛴다.
